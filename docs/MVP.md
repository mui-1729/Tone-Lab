# Tone Lab 2.0仕様

## ステータス

Tone Lab 2.0のソフトウェア実装は完了しています。APIテスト、Web単体テスト、ESLint、Next.js production build、Docker実行E2EをGitHub Actionsで自動検証します。

自動化できない最終工程は、Windows + Chrome + 実際のギター入力を使ったマイク権限・音声入力・聴感の確認です。

## ユーザーストーリー

ギタリストとして、参考音を用意し、自分の演奏を録音し、何が違うか、どの順番で何を調整すべきか、調整後に差が縮まったか、耳でも改善したと感じるかを1つのアプリで確認したい。

## 入力

- 参考音源ファイル
- 自分の音源ファイルまたはブラウザ録音
- 対応形式: WAV / MP3 / FLAC / OGG
- 最大サイズ: 1ファイル25MB
- 解析対象: 最大30秒
- 推奨: 同じフレーズ、ギター単体、近い演奏テンポ

### 参考区間

- 長い参考音から開始・終了位置を選択
- 5秒・10秒・15秒の区間プリセット
- 選択区間をループ再生
- 選択区間だけをブラウザ内でWAVへ切り出して解析

### ブラウザ録音

- マイク・USBオーディオ入力を選択
- 録音中のレベルとクリッピングを表示
- 参考区間の長さを録音上限へ反映
- 録音完了後は通常の音声ファイルとして既存APIへ送信

## 前処理

- 44.1kHz・モノラルへ統一
- 最大±5秒の開始位置ずれを自動探索
- オンセット強度と短時間RMSから一致度を計算
- 一致度が低い場合は誤補正せず警告
- 重複区間だけを比較
- 周波数・質感分析ではRMSを揃え、単純な音量差を除外

## 入力品質診断

- 空ファイル拒否
- クリッピング候補率
- 0dBFS付近のピーク
- 極端に小さい平均音量
- 2音源間の大きな平均音量差
- 位置合わせ一致度不足

## 出力

### 物理特徴

- RMS音量
- ピーク音量
- クレストファクター
- ダイナミックレンジ
- スペクトル重心
- スペクトル帯域幅
- 85%ロールオフ周波数
- 帯域内スペクトル平坦度
- ゼロ交差率
- オンセット強度
- 周波数帯ごとのエネルギー比率

### 質感差

比較値は`-100〜+100`です。正は「自分の音のほうが強い」、負は「参考音のほうが強い」を表します。

- Brightness / 明るさ
- Body / 太さ
- Attack / アタック
- Compression / 圧縮感
- Roughness / 粗さ

### 実用支援

- 差が大きい上位3項目の優先調整プラン
- 1項目ずつ小刻みに変更し、再解析する手順
- 音量エンベロープと平均周波数分布
- 位置同期・音量マッチ付きA/B試聴
- Markdown / JSON / 印刷レポート
- 5軸ごとの人間評価JSON

## 調整セッション

- 参考音、解析済み参考区間、各テイク、結果、変更メモをIndexedDBへ保存
- セッション名変更、再開、個別削除、全削除
- テイクごとの5軸推移と前回比
- 参考との差の絶対値合計を進捗指標として表示
- 直近最大3テイクの中央値を代表値として使用
- 中央値絶対偏差と方向一致率から演奏間ばらつきを表示
- 位置一致、入力警告、ばらつき、方向一致、差の大きさから軸別信頼度を算出

## ブラインドA/B

- 最新2テイクをランダムにX/Yへ割り当て
- 参考音・X・Yを共通のフレーズ位置で再生
- 各テイクの位置補正を参考音タイムラインへ変換
- 3音源を共通目標RMSへ下げて音量マッチ
- 回答前はファイル名と調整前後を表示しない
- X / Y / 判断できないを回答後にだけ公開
- 回答履歴をセッションへ保存

## 聴感評価ダッシュボード

- 複数の評価JSONをブラウザ内だけで読み込み
- schema version 1〜3へ後方互換
- 不正ファイルの理由付きスキップ
- 同一評価の重複除外
- 軸別の合っている / 違う / わからない / 未評価を集計
- 一致率の分母は「合っている + 違う」
- 予測差を大きさ別に集計
- 位置合わせ低信頼、入力警告、方向不一致、全体不一致を一覧化
- 集計JSONと軸単位CSVを保存

## リアルタイム比較

- AudioWorkletでモノラルPCMを継続取得
- 直近4秒だけをローリング保持
- 約1秒ごとに既存比較APIへ送信
- 最低3秒未満、無音、解析中は更新を保留
- 最大5回の結果を中央値で統合
- 入力レベル、クリッピング、5軸、信頼度、ばらつきを表示
- 停止時に最後の4秒を通常テイクとして保存
- localhost / HTTPSまたはAudioWorklet非対応時は通常比較へ案内

## データとプライバシー

- APIへ送った音源は解析中だけ一時保存し、処理終了後に削除
- サーバー側データベース、ユーザー登録、クラウド同期なし
- 参考音、各テイク、解析結果、ブラインド回答はブラウザのIndexedDBへ保存
- 評価JSONの集計はブラウザ内だけで実行
- 利用者はライブラリ画面から保存内容を削除可能

## 自動受入条件

- APIテストが成功
- Webの純粋計算ロジック単体テストが成功
- Web lint・production buildが成功
- Docker ComposeでWeb/APIが起動
- Webと`/health`が応答
- 生成WAVによる比較APIのE2Eが成功
- APIが位置合わせ、品質診断、5軸、可視化、調整プランを返す

## 実機・聴感受入条件

- Windows + Chromeで起動できる
- USBオーディオ入力を選択し録音できる
- 参考区間選択、録音、比較、次テイク、履歴再開が一連で動く
- リアルタイム比較を開始・停止し、最後の結果を保存できる
- A/B切替時の位置と音量が不自然に飛ばない
- ブラインド回答と評価JSONを保存できる
- ブラウザ再起動後も端末内セッションを再開できる

詳細手順は`docs/REVIEW_CHECKLIST.md`に記載します。

## 既知の制約

- 開始位置は補正するが、演奏途中のテンポ差は補正しない
- バンドミックスからギターを分離しない
- 質感値は物理特徴から作ったルールベースの仮説的指標
- ブラウザ保存を消去すると端末内ライブラリも消える
- リアルタイム表示は約1秒周期の調整支援であり、測定器用途ではない
- HX Stomp固有の機種設定やプリセット転送は行わない
- 機械学習による個人最適化は行わない

## ギター抽出アシストの採否

2.0では不採用です。正解ギターステムを持つ利用許諾済み10曲以上がない状態で分離品質を保証できず、分離ノイズが明るさ・粗さへ与える影響を安全に校正できないためです。詳細は`docs/GUITAR_EXTRACTION_DECISION.md`を参照してください。

## 完成の定義

Tone Lab 2.0は、参考音の準備、演奏録音、比較、調整、再録音、複数テイク統合、ブラインド聴感確認、評価集計、端末内再開、リアルタイム調整までを特定機材に依存せず完結できる状態をソフトウェア完成とします。
