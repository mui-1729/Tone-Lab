# Tone Lab MVP 1.0仕様

## ステータス

ルールベースMVPの実装は完了しています。ソフトウェア上のAPIテスト、Web production build、Docker実行E2Eは自動検証済みです。

残る受入工程は、実際のギター・HX Stomp・録音環境を使った最終的な聴感レビューです。

## ユーザーストーリー

ギタリストとして、参考音と自分の録音を比較し、何が違うか、どの順番で何を調整すべきか、調整後に差が縮まったかを知りたい。

## 入力

- 参考音源
- 自分の音源
- 対応形式: WAV / MP3 / FLAC / OGG
- 最大サイズ: 1ファイル25MB
- 解析対象: 冒頭から最大30秒
- 推奨: 同じフレーズ、ギター単体、近い演奏テンポ

## 前処理

- 44.1kHz・モノラルへ統一
- 最大±5秒の開始位置ずれを自動探索
- オンセット強度と短時間RMSから一致度を計算
- 一致度が低い場合は誤補正せず警告
- 重複区間だけを比較
- 周波数・質感分析ではRMSを揃え、単純な音量差を除外

## 入力品質診断

- 空ファイル拒否
- クリッピング候補率
- 0dBFS付近のピーク
- 極端に小さい平均音量
- 2音源間の大きな平均音量差

## 出力

### 物理特徴

- RMS音量
- ピーク音量
- クレストファクター
- ダイナミックレンジ
- スペクトル重心
- スペクトル帯域幅
- 85%ロールオフ周波数
- 帯域内スペクトル平坦度
- ゼロ交差率
- オンセット強度
- 周波数帯ごとのエネルギー比率

### 質感差

比較値は`-100〜+100`です。正は「自分の音のほうが強い」、負は「参考音のほうが強い」を表します。

- Brightness / 明るさ
- Body / 太さ
- Attack / アタック
- Compression / 圧縮感
- Roughness / 粗さ

### 実用支援

- 差が大きい上位3項目の優先調整プラン
- 1項目ずつ小刻みに変更し、再解析する手順
- 音量エンベロープと平均周波数分布
- 位置同期・音量マッチ付きA/B試聴
- Markdown / JSON / 印刷レポート
- 5軸ごとの人間評価JSON

## データとプライバシー

- 音源は解析中だけ一時保存し、処理終了後に削除
- データベース・ユーザー登録・サーバー側履歴なし
- レポートと人間評価はユーザー端末へ保存

## 自動受入条件

- APIテストが成功
- Web lint・production buildが成功
- Docker ComposeでWeb/APIが起動
- Webと`/health`が応答
- 生成WAVによる比較APIのE2Eが成功
- APIが位置合わせ、品質診断、5軸、可視化、調整プランを返す

## 実機・聴感受入条件

最低20組の実音源で、上位3つの差分説明について、評価者の70%以上が「方向性は納得できる」と回答すること。

アプリには評価JSONの保存機能があるため、この基準はコード変更なしで計測できます。これは最終的な精度目標ではなく、ルールベースMVPを学習段階へ進める判断基準です。

## 既知の制約

- 開始位置は補正するが、演奏途中のテンポ差は補正しない
- 別フレーズやバンドミックスは対象外
- 質感値は物理特徴から作った仮説的指標
- HX Stomp固有の機種設定やプリセット転送は行わない
- 機械学習による個人最適化は行わない

## 完成の定義

MVP 1.0は、2音源を安全に比較し、差を説明し、耳で確認し、次の調整を提示し、結果と人間評価を保存できる状態を完成とします。機械学習モデルと実機プリセット生成は、MVP 1.0で収集した評価データを利用する別フェーズです。
